# 14일 TIL

> 학습용 가상 기록입니다. 저장소의 실제 진행 이력은 열린 이슈 #1 `배포됨` 하나이며, 아래 일별 활동은 실제로 수행된 작업 기록이 아닙니다.

| 일차 | 오늘 배운 점 |
|---|---|
| 1일 | 저장소를 만들고 이슈로 작업을 추적하는 흐름을 익혔다. |
| 2일 | 이슈 제목은 작업 결과가 한눈에 보이도록 짧게 쓰는 편이 좋다. |
| 3일 | 작업 전에 완료 조건을 정하면 진행 여부를 판단하기 쉽다. |
| 4일 | 작은 단위로 커밋하면 변경 이유를 되짚기 편하다. |
| 5일 | README에 실행과 배포 방법을 정리하면 인수인계가 쉬워진다. |
| 6일 | 환경 변수와 비밀 정보는 코드에 직접 넣지 않아야 한다. |
| 7일 | 배포 전 빌드와 기본 동작을 확인하면 초기 오류를 줄일 수 있다. |
| 8일 | 배포 환경과 로컬 환경의 차이가 장애 원인이 될 수 있다. |
| 9일 | 배포 후 실제 URL에서 핵심 기능을 확인해야 한다. |
| 10일 | 로그와 상태 확인 방법을 미리 정해두면 문제 파악이 빨라진다. |
| 11일 | 이슈 상태와 실제 작업 상태를 일치시키는 것이 중요하다. |
| 12일 | 배포 절차를 문서화하면 반복 작업의 누락을 줄일 수 있다. |
| 13일 | 변경 사항과 알려진 제한점을 함께 기록하면 다음 작업에 도움이 된다. |
| 14일 | 완료 표시는 검증 결과와 연결되어야 신뢰할 수 있다. |
